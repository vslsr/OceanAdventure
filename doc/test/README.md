# 测试协议

> 规则本身是硬性的，见 [`AGENTS.md`](../../AGENTS.md) 的「交给别人执行的验证必须带协议」。
> 这里放的是它的骨架与模板——太长，不适合塞进那几条硬性禁令里。


这里每份文档描述**一组可以交给别人执行的测试**：怎么跑、预期什么、把什么贴回来。

## 为什么要有这一层

执行的人和写代码的人常常不是同一个，也可能是另一个 agent。
「我跑了，没问题」和「我跑了，第 3 条报 `CellCodeAt(12345, -7, 13) = 0102, expected 0103`」
之间的差别，决定了下一步是继续做还是返工——而**判断该贴什么回来，不该由执行者临场决定**。
执行者只需要照做和填空；判读留给拿到结果的人。

这一层解决的是一类具体的浪费：结果回报得太模糊，于是要多问一轮；或者执行者自己判断
「这个报错应该不重要」而没贴，于是往错误方向查。

## 每份文档必须有四节

| 节 | 作用 |
| --- | --- |
| **前置条件** | 不满足就别跑——跑了也是无效结果，比不跑更糟，因为它看起来像数据 |
| **执行** | 可直接粘贴的命令。**不写编辑器菜单路径**，理由见 `AGENTS.md` 的「按 UE 5.7 的实际情况写」 |
| **预期** | 逐条列出，每条给出明确的成功判据；判据要能被一眼判定，不能是「看起来正常」 |
| **报告模板** | 执行者填空后**整段**贴回 |

## 结果只有三种状态

| 状态 | 含义 | 必须附带 |
| --- | --- | --- |
| `PASS` | 全部预期都满足 | 成功标记那几行 |
| `FAIL` | 有预期不满足 | **原始输出**，从第一条报错到结尾；不要转述、不要节选「关键部分」 |
| `BLOCKED` | 前置条件不满足，没跑成 | 是哪一条前置没满足，以及当时的输出 |

**不接受只回「通过」或「有问题」。** 前者无法复核，后者无法定位。

## 给执行者的三条

1. **按顺序跑，不要跳。** 前面的步骤通常是后面的前置。
2. **第一个失败就停下回报**，除非文档明说要继续。后续失败往往是它的下游，一起贴反而淹没根因。
3. **不要自行判断某条报错「应该不重要」。** 判读不是执行者的职责——贴回来，由拿到结果的人决定。
