# 海战大逃杀 P0–P5 设计 MVP 循环方案

> 项目：OceanAdventure  
> 依据：Naval-Battle-Royale-Game-Design.md（2026-08-21 更新版）  
> 文档定位：把设计总纲第 19 章展开为六个可独立开局、游玩、结束、复盘和决定去留的阶段门  
> 状态：建议稿  
> 目标模式：休闲 TopDown / 角色直控 / 海战 / 单层建造 / PvPvE / 单局成长 / 大逃杀

## 0. 结论

P0–P5 不应被理解为“功能不断累加的六张清单”，而应是六个依次回答不同风险问题的可玩产品：

| 阶段 | 可玩版本 | 唯一主问题 | 建议规模 | 单局时长 | 阶段产出的决定 |
| --- | --- | --- | ---: | ---: | --- |
| P0 | 舰岛攻防玩具 | 角色、墙体、重炮、木筏和主舵台能否共用一套可信战斗语言 | 2–4 人 | 6–8 分钟 | 核心手感是否值得继续 |
| P1 | 靠岸迁营局 | 靠岸、插旗、取材、装船、迁营是否形成风险循环 | 4–6 人单排 | 9–11 分钟 | 地面据点是否真的服务海战 |
| P2 | 压缩大逃杀 | 完整“搜集—兑现—构筑—交战—迁徙—决胜”是否成立，哪种收束规则更好 | 8–12 人单排 | 12–15 分钟 | 传统缩圈或灯塔迁徙二选一 |
| P3 | 双人垂直切片 | 8 支双人队的约 20 分钟产品承诺是否成立 | 16 人 | 18–21 分钟 | 核心产品形态是否成立 |
| P4 | 重复游玩 Alpha | 同一玩家连续游玩后，路线、构筑和事件是否仍有变化与学习空间 | 16 人 | 约 20 分钟 | 内容宽度与新手承接是否足够 |
| P5 | Season 0 候选 | 陌生玩家能否稳定匹配、完成、结算、复盘并再次排队 | 16 人 | 约 20 分钟 | 是否具备封测/发布候选资格 |

建议对原设计总纲第 19 章做如下映射：

- 原 P0 保留为新 P0，但补齐“主舵台—舵芯总成—舵叶—推进件”的分层验证和明确终局。
- 原 P1 过载，拆成新 P1 的靠岸迁营循环和新 P2 的完整压缩大逃杀。
- 原 P2 顺延为新 P3，并把双人分工、20 分钟节奏和 Dedicated Server 作为硬门槛。
- 原 P3 拆成新 P4 的内容/留存验证和新 P5 的排位、反作弊、回放与运营稳定性验证。

## 1. 六阶段共同规则

### 1.1 “可玩”的最低定义

每个阶段都必须同时具备：

1. 明确开局：玩家知道自己是谁、船在哪里、第一目标是什么。
2. 至少一次成长：角色、据点或木筏发生可感知改变。
3. 至少一次风险决策：收益更高的路线同时增加暴露、损失或迁徙成本。
4. 至少一次可反应冲突：能预警、能规避、能反制，不能只打静态靶。
5. 明确结束：淘汰、占领或限时判定，不允许以“大家玩够了就停”代替结算。
6. 一键重开或回到下一局：验证“是否愿意立即再玩”而不是只验证功能能否触发。

### 1.2 不随阶段妥协的硬规则

- 玩家始终以 TopDown 方式直接控制角色，操舵和操作重炮只是角色进入设施状态，不切换成另一套游戏。
- 普通墙阻挡敌我双方的直接弹道、爆炸与压制；只有合法友方从内向外通过单向射击窗。
- 主舵台负责操作与夺船交互，真正受击体是加固舵芯座；船壳、舵芯、舵叶和推进件是不同状态。
- 地面重武器自带支架，不以战旗或地基为工作前提；建筑只提供防护、供弹和炮窗协同。
- 所有船只与建筑状态由服务器写入；客户端只做幽灵预览、瞄准预测和表现。
- 主船失能不等于队伍立即淘汰；从 P0 起就保留抢修或救生筏继续参与的路径。
- 建筑始终无屋顶、无二层，木筏也保持单层和清晰轮廓。
- 每个阶段只有一个主假设。未通过时优先修改当前阶段，不用新增内容掩盖问题。

### 1.3 总体递进关系

P0 先证明“打起来好玩”  
→ P1 证明“为什么要离船、建造和迁移”  
→ P2 证明“完整局为什么比纯海战更有张力，并选定收束规则”  
→ P3 证明“20 分钟双人产品形态成立”  
→ P4 证明“玩家愿意重复玩”  
→ P5 证明“陌生玩家可以稳定地一直玩下去”

## 2. P0：舰岛攻防玩具

### 2.1 核心假设

“角色轻武器侧移反制慢重炮、墙/炮窗改变射界、木筏用船身取向换取侧舷火力、主舵台受损后仍有抢修窗口”这一组关系本身足够有趣，而且玩家不需要设计者口头解释弹道例外。

### 2.2 可玩循环

出生在 T0 小筏  
→ 驶向中央岛并拾取一组固定物资  
→ 扩一格甲板，在地面或船上部署同一门重炮  
→ 用普通墙/单向窗建立一次射界  
→ 与敌方进行角色战和舰战  
→ 船壳或舵芯失能后抢修、弃船或部署救生筏  
→ 淘汰对手或占领中央信标  
→ 立即重开

### 2.3 一局脚本

| 时间 | 内容 | 设计目的 |
| --- | --- | --- |
| 0:00–1:30 | 两侧近岸出生；中央资源足够完成一段防护和一次扩筏 | 30 秒内给出有效行动，避免空航行 |
| 1:30–5:30 | 中央岛、两条侧航道和开阔水面同时可用；玩家选择地面架炮或船载炮 | 验证墙、窗、轻重武器和船身射界 |
| 5:30 | 中央信标启动并公开所有存活目标的大致方向 | 阻止绕圈和躲藏 |
| 5:30–8:00 | 占领 30 秒或淘汰全部敌方获胜；超时按存活角色、占领进度、有效船壳判定 | 保证每局结束 |

### 2.4 最小内容

- 1 张固定灰盒海域：2 个出生湾、1 座中央岛、2 条侧航道、1 个骤死信标。
- 1 艘 T0 木筏；1 个主舵台/舵芯总成；1 个推进件；1 个舵叶；1 个浮筒。
- 船壳、推进、舵叶、舵芯四类状态；正常、失能、残骸状态链；基础修理与一次团队救生筏。
- 2 种射程不同的轻型武器，验证两个通用槽、拾取替换、切换锁和换弹状态继承。
- 1 种地面/船载共用的重型炮；具备部署前摇、施工态、慢弹道、最小射距和离炮动作。
- 1 种地板、1 种普通墙、1 种单向射击窗、1 个木筏功能件。
- 离散吨位、浮力容量、推力、超载分档和浮筒损坏后的危险吃水。
- 最小 HUD：角色状态、两武器槽、船壳/舵芯/舵叶/推进、炮口阻挡、载重/推力、结束条件。

### 2.5 明确不做

- 不做完整采集经济、价值货物、商店、钓鱼、PvE、Seed 地图、核心等级、T2/T3、局外成长。
- 不做双人岗位设计；2–4 人用于对抗，不用队友协作掩盖单人操控问题。
- 不做最终美术，只要求团队归属、窗内外、重炮预警和受损状态可读。

### 2.6 验证与通过门槛

至少完成 12 局内部盲测，并在不口头解释规则的情况下记录：

| 指标 | 通过门槛 |
| --- | --- |
| 首次有效行动 | 95% 测试者在 30 秒内完成 |
| 墙/窗理解 | 80% 以上测试者能正确复述普通墙与友方单向窗的区别 |
| 轻武器反炮窗口 | 重炮射失后，对手能够观察并至少尝试侧移、打施工炮或打操作者 |
| 同阶正面对舰 | 击沉时间落在约 70–100 秒；优势伏击约 35–50 秒 |
| 主舵台理解 | 测试者能区分“舵芯失能无法主动操控”和“船壳归零开始沉没” |
| 失船后参与 | 90% 以上存活玩家在 45 秒内继续移动、抢修或部署救生筏 |
| 规则一致性 | 墙后受直击、爆炸或压制伤害的错误为 0；切换武器绕过状态的错误为 0 |
| 再玩意愿 | 70% 以上测试者愿意立即再开一局，并能说出一个下一局想改变的战术 |

若 P0 未通过，停止加入经济和 PvE；优先修正移动响应、瞄准反馈、射界、墙体碰撞和船只失能节奏。

## 3. P1：靠岸迁营局

### 3.1 核心假设

玩家愿意为了资源离开移动主基地，并认为“插旗建小据点—守住收益—打包重点套件—装船迁往下一岛”是有价值的决策，而不是额外作业。

### 3.2 可玩循环

从近岸木筏选择安全岛或争夺岛  
→ 靠岸、插下基础据点战旗  
→ 用墙/窗/门保护采集和一门地面重炮  
→ 把四类资源搬回船舱  
→ 在修船、补弹、T1 航行/火力/承载之间取舍  
→ 根据灯塔预报打包关键套件并搬回船  
→ 迁往中央群岛交战  
→ 王冠信标占领或最后存活获胜

### 3.3 一局脚本

| 时间 | 内容 | 设计目的 |
| --- | --- | --- |
| 0:00–1:00 | 近岸出生，可见一条安全路线和一条高收益路线 | 建立首次航线选择 |
| 1:00–4:00 | 登岛、插旗、采集、地面架炮、第一次装船 | 证明离船风险和据点阶段价值 |
| 4:00–6:30 | 下一活跃群岛预报；玩家选择继续守收益或提前打包 | 产生“多拿一点还是安全撤离”的决策 |
| 6:30–9:00 | 三条迁徙路线汇入中央群岛；完成一次 T1 改装并发生 PvP | 把建造、运输和舰战接起来 |
| 9:00–11:00 | 王冠信标开放，停止资源刷新 | 强制决胜并验证携带套件的再部署价值 |

### 3.4 最小内容

- 4–6 人单排，固定的三岛链灰盒地图；不用随机 Seed。
- 4 种常规资源，资源语义与正式版一致；大宗资源必须进入船舱。
- 1 个基础建筑锚核/据点战旗；核心地基是第一格；每核 8–12 个基础结构与最多 2 个连接式功能件。
- 地板、墙、单向窗、门、资源箱、1 个功能设施；地面重炮仍受独立队伍上限管理。
- 建筑打包 6–8 秒、迁移箱实体搬运、战斗中断、受损套件和返还预览。
- 每条成长路线至少 1 个 T1 代表模块；不做 T2。
- 一次灯塔迁徙和一次王冠占领；主船失能、救生筏和基础抢修沿用 P0。
- 最小阶段信息：当前/下一活跃群岛、预计航行时间、据点剩余有效时间。

### 3.5 明确不做

- 不做价值货物、团队金币、贸易站、漂流商船、钓鱼、PvE、第二锚核、T2/T3、恶名和程序地图。
- 不做完整装备栏；P0 的双轻武器继续使用，投掷物、补给品和护甲留到 P2。
- 不做保险自动回收；P1 先验证玩家是否主动愿意打包，避免系统替玩家完成核心行为。

### 3.6 验证与通过门槛

| 指标 | 通过门槛 |
| --- | --- |
| 首次建造或扩筏 | 中位数 2–3 分钟 |
| 建造参与 | 90% 以上玩家至少完成一次地面建造或木筏扩建 |
| 据点有效时长 | 中位数 2.5–5 分钟，且至少服务一次采集、守点或装船 |
| 主动迁营 | 60% 以上据点的关键功能件被主动打包并成功返船 |
| 打包可读性 | 玩家能在开始前说清保留什么、损失什么、需要多少货位 |
| 资源取舍 | 80% 以上测试者能复述一次“修理/弹药/T1”之间的真实取舍 |
| 首次 PvP | 中位数 4–6 分钟；80% 以上玩家经历可反应 PvP |
| 空白时间 | 连续两分钟无有效行动的玩家低于 10% |
| 定性归因 | 80% 以上玩家认为据点帮助了收益或撤离，而非单纯拖慢节奏 |

若主动迁营率低，先判断是预报、打包时长、货位还是建筑本身回报不足；不得直接增加自动保险回收掩盖问题。

## 4. P2：压缩大逃杀

### 4.1 核心假设

加入价值货物、贸易购买、钓鱼补给、PvE、自由装配和多轮收束后，玩家能够在 12–15 分钟内反复做出“去哪、怎么花、何时打、何时兑现”四类决策；同时用同图同经济 A/B 测试选出唯一收束规则。

### 4.2 可玩循环

观察粗略海图并选择出生航道  
→ 登岛/打捞/拖钓，获得资源与价值货物  
→ 回船装载，选择继续搜或前往贸易点兑现  
→ 购买补给、情报或 T1 构筑并安装  
→ 建据点、争公开事件、形成 T2 构筑  
→ 击沉/掠夺/夺船或避战迁徙  
→ 进入缩圈或灯塔终局  
→ 结算并立即重排

### 4.3 一局脚本

| 时间 | 内容 | 设计目的 |
| --- | --- | --- |
| 0:00–3:00 | 出生航道、第一岛、第二轻武器机会、首个低价值兴趣点 | 快速拥有与路线选择 |
| 3:00–7:00 | 首次出售、购买、T1、第一次 PvP；下一阶段预报 | 验证搜打撤经济是否只是可选路线 |
| 7:00–11:00 | 公开事件、T2、第二据点或高价值货物、恶名启动 | 制造多队冲突和领先者暴露 |
| 11:00–15:00 | 最后消费窗口、终局汇聚、占领或淘汰 | 验证可靠收束 |

### 4.4 最小内容

- 8–12 人单排，12–15 分钟压缩局。
- 3–4 个高质量岛屿模板和少量战术骨架；所有候选 Seed 经过出生保底、主海域连通、资源可达、航线宽度和完整阶段序列验收。
- 4 种常规资源；2 类价值货物兴趣点；2 座岛屿贸易站；1 艘固定公开航线的漂流商船；团队金币；6–8 个确定商品。
- 1 种普通 PvE；1 个公开事件；1 根拖钓线、1 类鱼群点、3 种鱼获。
- 同一种通用船芯和数据化自由配件；四条升级路线各 2 个模块，最高 T2。
- 完整 2 + 1 + 1 + 1 战斗栏、最多两类轻型弹药、死亡战利品和至少两组互补双武器组合。
- 木筏核心和建筑核心 T0–T2、一个横向特性槽、实体核心箱、脱战安装。
- 基础/扩展锚核、最多两座据点、共享结构预算、受损套件、夺船、一队一主船、一次基础船重建和基础恶名。
- 粗略海图、接近测绘、衰减敌情、下一活跃区域公告和一条适配当前主船的安全建议航线。
- 两套独立规则开关：A 为传统缩圈 + 打包返还；B 为三轮灯塔迁徙 + 结构套件 + 王冠灯塔。两套规则不得在同一局混用。

### 4.5 明确不做

- 不做 T3、世界 Boss、双人倒地救援、动态市场、船载出售、局外仓库、商人好感和真实撤离胜利。
- 不做未经验证的纯随机 Seed；运行时失败直接回退人工安全 Seed。
- 不做排位、赛季、商业化和最终美术。

### 4.6 验证与通过门槛

建议 A/B 各完成不少于 20 局有效测试，固定地图池、资源表、人数档和玩家水平分布。

| 指标 | 通过门槛 |
| --- | --- |
| 完成升级 | 85% 以上队伍 |
| 建造参与 | 90% 以上队伍 |
| 可反应 PvP | 80% 以上队伍 |
| 出售参与 | 45%–75% 队伍至少出售一次；不能接近强制主线 |
| 首次兑现 | 中位数 4–7 分钟 |
| 有效购买 | 正常存活队伍中位数 2–4 次，且覆盖至少两种商品类别 |
| 地图公平 | 最优/最差出生扇区 T1 机会差不超过 15 秒或 20% |
| 安全航线 | 因静态地形搁浅低于 0.5%；ETA 晚于失活却不预警为 0 |
| 构筑垄断 | 单一构筑簇长期不高于 45%–50% |
| 经济归因 | 玩家能说清一次携货继续冒险或返航兑现，以及当前购买理由 |

收束规则选择门：

1. B 版若让“系统没收基地”的负面反馈明显下降，并使重复部署/主动迁徙率至少提高约 15 个百分点，同时终局参与、首次 PvP 和时长不劣于 A 版，则 P3 固定采用灯塔迁徙制。
2. A 版若在建造意愿相当时明显更易理解、终局更稳定且迁移作业更少，则 P3 固定采用传统缩圈。
3. 结果不明确时，只延长 P2；不得把两套收束同时带入 P3。

## 5. P3：双人垂直切片

### 5.1 核心假设

8 支双人船队能在约 20 分钟内完成“建立立足点—第一次迁徙—构筑成形—群岛汇聚—海冠决战”，两名玩家有自然分工但可随时换位，并且服务器能够稳定承载角色、AI、炮弹、船体部件和地面结构同时复制。

### 5.2 可玩循环

双人选择出生航道并站在同一艘 T0 木筏上  
→ 一人操船、一人测绘/准备靠岸  
→ 登岛插旗、采集、搜货并决定是否留人看船  
→ 出售、购买、改装、钓鱼或参与 PvE  
→ 多轮迁徙中打包据点、应对登船和船损  
→ 形成 T2/T3 构筑并争夺世界事件  
→ 最终群岛舰战、破墙、倒地救援和王冠占领  
→ 团队结算

### 5.3 一局脚本

| 阶段 | 时间 | 主要行为 |
| --- | ---: | --- |
| 建立立足点 | 0–4 分钟 | 靠岸、首批资源、基础战旗、首次出售或升级 |
| 第一次迁徙 | 4–9 分钟 | 打包、拖钓/打捞、航线风险、扩展锚旗争夺 |
| 构筑成形 | 9–14 分钟 | T2/T3 方向、第二功能据点、PvP/PvE、贸易最终准备 |
| 群岛汇聚 | 14–18 分钟 | 高密度船战、破墙、抢修旗座、夺船和最后消费窗口 |
| 海冠决战 | 18–20 分钟 | 停止普通收益，王冠占领或全员淘汰 |

### 5.4 最小内容

- 8 队 × 2 人，18–21 分钟目标，约 21 分钟硬设计目标；极端局不超过 24 分钟。
- 4–6 个可读岛屿模板、通过验证的 Seed 池、完整五阶段收束序列。
- 2 类普通 PvE、1 个世界 Boss、T3 风暴核心和可识别的高阶前摇。
- 完整地面建造与木筏改造轮盘、布局蓝图、保险/受损套件规则，以及 P2 胜出的唯一收束机制。
- 登船、倒地救援、落水营救、救生筏、基础船重建、主船夺取和一队一主船。
- 适合双人的操船、火炮、损管、侦察和搬运交互；所有岗位允许短时间离开，禁止长期自动驾驶。
- 基础航海 HUD、战斗栏、重炮 HUD、船体剖面、战术海图、团队状态、结算和完整埋点。
- 使用 Lyra Experience 装配模式；角色能力由 AbilitySet 授予，输入由 Enhanced Input + InputTag 注入，反馈用 Gameplay Message，UI 使用 CommonUI 层栈。

### 5.5 明确不做

- 不做大量内容扩展、赛季任务、排位、正式商店、跨赛季库存、4 人舰队或多个主船。
- 不用更多 AI 或更强奖励弥补玩家相遇密度不足。
- 不在 P3 同时大改核心循环与扩充内容；P2 选定的收束规则进入冻结期。

### 5.6 验证与通过门槛

| 指标 | 通过门槛 |
| --- | --- |
| 对局时长 | 中位数 18–21 分钟，95% 在 24 分钟内结束 |
| 服务器完成率 | Dedicated Server 连续多轮完整开局、结算、重开，无阻断性复制错误 |
| 终局参与 | 80% 以上终局存活队伍进入目标区、攻击目标区或贡献占领 |
| 双人分工 | 两名成员都在至少两类行为中产生有效贡献，不存在固定岗位长期无事可做 |
| 主舵岗位 | 无人控制时长和连续操舵时长不形成“舵手整局无法参与战斗”的主流模式 |
| 失船继续参与 | 80% 以上首次失船队伍继续移动、重建、夺船或有效战斗 |
| 墙阵统治 | 不存在单一墙阵或单入口稳定封锁终局；至少三条进攻路径实际被使用 |
| 成长健康 | 无单一模块选择率长期超过 60%；最高阶通常每船 1 个，极富队伍最多 2 个 |
| 死亡可解释 | 80% 以上测试者能复述关键错误、伤害来源和可用反制 |

P3 通过意味着“核心产品形态成立”，不是“内容已经足够发布”。

## 6. P4：重复游玩 Alpha

### 6.1 核心假设

在核心循环不变的前提下，地图骨架、岛屿模板、事件、横向模块和局外目标能让同一玩家连续游玩多局仍产生不同路线、构筑和故事；新玩家也能在不依赖开发者陪玩的情况下进入循环。

### 6.2 可玩循环

完成 8–10 分钟序章或进入新手池  
→ 选择航海日志挑战与外观配置  
→ 匹配进入完整 20 分钟对局  
→ 依据本局 Seed、天气、事件和队友形成不同路线/构筑  
→ 结算名次、行为任务、图鉴和外观进度  
→ 查看回放片段/死亡原因  
→ 调整挑战、蓝图或外观后再次排队

### 6.3 最小内容

- 维持 P3 的 8 支双人队与唯一主模式。
- 扩展到 8–12 个高质量岛屿模板、至少 3 种战术骨架和一批离线验证的安全 Seed；避免连续重复宏观布局。
- 在不增加垂直数值上限的前提下，增加横向模块、角色工具、公开事件和 PvE 变体。
- 8–10 分钟独立序章，必须包含操船、靠岸、搬运、修理、侧舷射击、失能抢修、救生筏和一次基础船重建。
- 前 3 局新手池或明确标识的低难度 AI 船；首局任务只要求行为，不要求获胜。
- 航海日志、图鉴、赛季前置任务和外观奖励；不提供局内数值优势。
- 基础观战、死亡回放和可复现的 Seed/版本记录，既服务玩家理解也服务 QA。
- 统一美术主题、音频危险语言和关键模块轮廓；仍以竞技可读性优先。

### 6.4 明确不做

- 不做新主模式、4 人队、60 人规模、永久数值成长、玩家船出售、动态市场或局外装备仓库。
- 不为提高“内容数量”放宽 Seed 公平、航道连通、三入口终局和性能预算。
- 不用更多随机词条制造伪变化；变化来自路线、模块组合、事件和玩家行为。

### 6.5 验证与通过门槛

建议使用至少 30 名非开发测试者，每人完成序章和至少 5 局有效对局。

| 指标 | 通过门槛 |
| --- | --- |
| 无陪玩入局 | 90% 以上新玩家独立完成序章并进入首局 |
| 首局理解 | 能复述资源入船有风险、主船失能不等于立即淘汰、下一活跃区必须迁徙 |
| 重复意愿 | 多局测试后，过半玩家仍能说出下一局想尝试的新路线或构筑 |
| 地图重复感 | 不因连续出现相同宏观骨架或同一最优航线成为主要负反馈 |
| 构筑多样性 | 单一构筑簇不超过约 45%–50%，标准化胜率保持相近 |
| 搜打撤边界 | 出售参与保持 45%–75%，金币未成为所有队伍必做的唯一成长路线 |
| 钓鱼边界 | 尝试率 40%–70%，基础建造材料贡献不超过 5%–10% |
| 新手保护 | AI 明确标识；离开新手池后不存在隐藏数值补偿 |
| 死亡学习 | 80% 以上玩家能借助回放/提示说清失败原因 |

如果重复游玩意愿低，先检查是否存在固定最优路线、构筑垄断或空白航行；不要直接用更多奖励和任务强迫回流。

## 7. P5：Season 0 封测/发布候选

### 7.1 核心假设

陌生玩家能够在真实服务流程中完成“匹配—加载—游玩—断线恢复—结算—复盘—再排队”，公平性、服务器稳定性、反作弊与商业化边界不会破坏 P3/P4 已验证的玩法。

### 7.2 可玩循环

选择单一双人主模式与赛季挑战  
→ 匹配、组队、加载对应 Lyra Experience  
→ 完成约 20 分钟对局  
→ 结算名次、航海日志、排位和纯外观进度  
→ 举报/观战/回放或查看死亡原因  
→ 调整外观、任务和装配蓝图  
→ 再次排队

### 7.3 最小内容与系统

- 冻结 P4 的核心规则和首发内容池；P5 原则上不再加入新的核心玩法系统。
- Dedicated Server 匹配、组队、重连、弃赛、结算、赛后回队和再排队完整链路。
- 排位规则、赛季任务、观战、回放、举报和基础反作弊。
- Seed、模板、资源、配方、事件和阶段规则全部版本化；运行时生成失败回退已验证安全 Seed。
- 服务器性能、复制预算、相关性、FastArray 资产索引、库存守恒和异常恢复监控。
- 完整输入重绑定、手柄/键鼠路径、CommonUI 输入模式、无障碍方向提示和设置保存。
- 外观商业化只改变角色、船帆、旗面和特效表现，不增加船体血量、武器伤害、核心数量、资源效率或出生装备。
- Season 0 内容日历只调度已验证事件和横向奖励，不在赛季中热改墙体、弹道或主船状态等基础契约。

### 7.4 明确不做

- 不在发布候选阶段新增 4 人模式、第二艘主船、真正撤离模式、水下层、多层建筑或写实航海。
- 不出售强度，不把外观任务绑定为进入 T1/T2/T3 的条件。
- 不为了匹配速度把人数、队伍规模或 AI 填充规则悄悄改成未经验证的新模式。

### 7.5 验证与通过门槛

| 类别 | 通过门槛 |
| --- | --- |
| 流程完整性 | 匹配、加载、结算、回队、再排队无阻断；失败能回到可恢复状态 |
| 稳定性 | 有效对局完成率至少 98%；崩溃自由会话目标至少 99% |
| 时长 | 中位数 18–21 分钟，95% 在 24 分钟内结束 |
| 服务器 | 16 人 + 预算内 AI/炮弹/结构下满足目标 Tick；无持续超预算复制峰值 |
| 状态守恒 | 船体打包、夺船、救生筏、重建、交易和断线重连的复制/吞物错误为 0 |
| 公平 | 出生 T1 机会差、静态航线搁浅、风暴直接淘汰、单一贸易点和构筑垄断维持 P2–P4 健康区间 |
| 安全 | 已知作弊入口有服务端校验，异常输入和库存变化可审计 |
| 商业化 | 付费与长期成长不影响任何对局强度指标 |
| 回归 | P0 的墙窗规则、P1 的迁营价值、P2 的经济边界、P3 的双人节奏、P4 的重复游玩指标均未倒退 |

P5 只有在“技术稳定”和“玩法指标未回退”同时成立时才可通过。稳定但不好玩，或好玩但状态不守恒，都不是发布候选。

## 9. 实现归属与依赖护栏

本节只规定设计落地边界，不要求在本方案任务中立即重构代码。

| 归属 | 应承担的能力 | 不得承担 |
| --- | --- | --- |
| BuildingCoreRuntime | 通用网格、支撑/连接、放置预览、结构预算、通用复制、首个墙体阻挡契约 | Lyra、GAS、CommonUI、具体战旗/灯塔玩法 |
| OceanCoreRuntime | Ocean Chunk、岛屿模板装配、Seed、航道连通与静态航线数据 | 大逃杀阶段、玩家能力、贸易、UI |
| 建议的 RaftCore 通用插件 | 木筏网格、吨位/浮力/推力、舵芯/舵叶/推进/船壳状态、通用船体复制接口 | LyraGame、GAS、CommonUI、OceanAdventure 规则 |
| OceanAdventure GameFeature | Experience、PawnData、AbilitySet、InputConfig、角色装备、战旗/灯塔、贸易、PvE、恶名、队伍、UI、消息与胜负 | 依赖其他 GameFeature 或把专属资产放到项目 /Game |
| LyraGame | 只作为玩法层既有框架：Experience、GAS、Team、Inventory、GamePhase、CommonUI 和消息模式 | 承载 OceanAdventure 专属内容 |

当前工程需要在 P0 稳定基线前处理一个明确的依赖风险：OceanAdventure.uplugin 目前直接声明依赖 Raft 和 TopDownFeature 两个 GameFeature，这与“GameFeature 之间不得依赖”的项目规则冲突。建议选择以下落地方式之一，并记录迁移影响：

1. 将真正通用的木筏、TopDown 相机/控制能力下沉到无 Lyra 依赖的通用插件；OceanAdventure 只依赖这些通用插件。
2. 将只服务本模式的 Pawn、输入、相机、能力、UI 和内容合并归属到 OceanAdventure GameFeature。
3. Raft/TopDownFeature 若继续作为独立内容 GameFeature，只能由 Experience 并列激活，彼此通过通用接口或世界子系统协作，不能形成代码或资产依赖。

P0 起即遵守以下 Lyra 落地规则：

- Experience 负责阶段可玩包的装配；每个 P 阶段可有独立测试 Experience，但正式 P3 起只保留一个主模式 Experience。
- 玩家玩法能力通过 AbilitySet 授予；输入使用 InputAction、InputMappingContext、LyraInputConfig 和 InputTag，不硬编码按键。
- 角色发起的玩法请求走 GAS TargetData 并由服务器复检；失败与事件反馈使用 Gameplay Message。
- 能力性组件通过 GameFeatureAction_AddComponents 注入，不在角色构造函数中焊死。
- 鼠标、捕获和输入模式由 CommonActivatableWidget 的输入配置声明，不直接改 PlayerController 光标状态。
- OceanAdventure 专属资产、配置、脚本和 UI 全部位于 Plugins/GameFeatures/OceanAdventure/ 下。

## 10. 阶段门与复盘方式

每个阶段结束时只允许三种决定：

| 决定 | 含义 | 下一步 |
| --- | --- | --- |
| 通过 | 主假设成立，硬指标无阻断 | 冻结已验证契约，进入下一阶段 |
| 有条件通过 | 主假设大体成立，但一个可定位问题未达标 | 只做当前阶段的定向修正，再回归关键指标 |
| 不通过 | 主假设不成立，或失败原因无法归因 | 停止扩内容，重做当前循环或终止方向 |

每轮复盘固定输出一页记录：

1. 本轮只验证了什么。
2. 使用的 Experience、Seed、配方、资源和规则版本。
3. 指标结果及样本量。
4. 三段代表性录像：成功循环、失败但公平、失败且不可理解。
5. 玩家原话中的死亡/损失归因。
6. 下一轮只改哪三个变量；其余参数冻结。
7. 是否通过阶段门，以及不可逆内容制作是否可以开始。

## 11. 推荐立即执行顺序

1. 先冻结 P0 的固定地图、两把轻武器、一门重炮和四类船体状态，不继续扩资源/商店内容。
2. 在 P0 灰盒中先跑墙窗规则、主舵台损伤、重炮射失反杀和救生筏四个脚本化场景，再开放自由对战。
3. P0 通过后制作 P1 的三岛链、基础战旗和实体迁移箱；用同一批测试者观察据点是否带来新决策。
4. P1 通过后才接入贸易、钓鱼、PvE、双核心和受约束 Seed，组成 P2。
5. P2 完成 A/B 选择后删除落败收束规则在主线中的运行入口，再进入 P3 双人垂直切片。
6. P3 通过前不批量生产岛屿、Boss、外观和赛季内容；P3 通过后由 P4 扩内容，P5 只做运营化和回归收口。

这条路线的核心判断标准始终不变：当玩家满载资源、推进受损、迁徙倒计时临近且远处出现通缉舰时，玩家是否能立即看懂局势，并在修船、交战、弃货或改道之间做出一个没有标准答案的选择。
