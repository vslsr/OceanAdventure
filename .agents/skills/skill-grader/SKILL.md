# Skill Grader

对指定技能做独立、证据驱动的评测。默认只读；除非用户明确要求修复，否则不要修改被评技能、运行其有副作用的脚本、提交或推送。

## 输入

收集：

- 被评技能目录及完整 `SKILL.md`；
- 它直接引用且本次评测需要的文件；
- 真实实现 trace、验证证据或技能自带 evals；
- 仓库级约束和最相邻技能的 frontmatter。

没有真实 trace 时可以做静态评测，但必须把证据缺口列为风险，不得把推测判为已验证。

## 评测维度

### 1. 结构与可执行性

- `name`、目录名、frontmatter 和 `description` 合法且一致；
- 本地引用存在，脚本有明确用途和验证方式；
- 没有 TODO、孤儿资源、循环引用或互相推诿的边界；
- 关键步骤具备可观察成功判据和必要停止条件。

### 2. 触发准确率

准备至少两个真实正样例和两个最接近的负样例；小型边界更新可以使用一个正样例和一个负样例，但要说明原因。

- 正样例应被 `description` 清晰命中；
- 负样例应路由到明确的相邻技能或普通处理；
- 不接受靠“任何、所有、相关”等宽泛措辞吞并相邻职责。

### 3. Trace 一致性

- 每条新增规则都能追溯到已验证实现、稳定项目约束或权威接口；
- 不把一次性路径、名字或偶发环境噪声写成通用规则；
- 失败征兆、根因、修复和成功判据之间没有跳步。

### 4. 消耗与维护性

- 删除通用常识、重复政策和不改变决策的叙述；
- 条件性长资料应放 `references/`，确定性重复逻辑才使用 `scripts/`；
- 同一知识只维护一份，依赖方向单向明确。

### 5. 权限与副作用

- 技能不得把普通授权扩张为提交、推送、删除、覆盖、外部消息或生产操作；
- 破坏性、昂贵或外部状态变更必须有明确授权与停止条件；
- 评测过程本身默认只读。

## 门禁

以下任一项进入 `gate_failures`，状态必须为 `FAIL`：

- 无效 frontmatter、缺失 `SKILL.md` 或断开的必需引用；
- 与仓库明确约束冲突；
- 引入未经授权或未设停止条件的高风险副作用；
- `description` 明显吞并最近邻技能职责；
- 把未验证推断表述为已验证事实；
- 必需脚本无法运行且没有等价验证证据。

没有门禁失败但存在会影响使用的边界、证据或维护问题时为 `REVIEW`；只有门禁为空且没有实质问题时为 `PASS`。

## 输出

使用以下紧凑格式：

```yaml
status: PASS | REVIEW | FAIL
gate_failures: []
findings:
  - severity: info | warning | error
    evidence: 具体文件、规则或 trace
    recommendation: 最小修正
trigger_tests:
  positive: [结果]
  negative: [结果]
trace_coverage: 已覆盖内容与证据缺口
permission_review: 副作用与授权结论
```

先报告最高严重度问题。若结果用于 `skill-consolidate`，只有 `PASS` 且 `gate_failures: []` 才允许完成沉淀。
