# Python Script Governance

降低项目 Python 自动化对运行时反射、宿主解释器和资产状态的盲猜。核心要求是：**先读失败档案，再碰脚本；脚本一旦报错，先留档，再修改。**

## 强制进入顺序

每次创建、修改、审计、排查或准备执行仓库中的 Python 脚本时，必须按顺序完成：

1. 完整阅读本文件。
2. 完整阅读 [Python 失败档案](references/error-ledger.md)，不得只搜索当前报错关键词。
3. 在 commentary 中说明已读档案，并列出与当前任务相关的错误 ID；没有相关项时明确写“无已知同类错误”。
4. 选择并完整阅读领域 Skill：
   - Lyra 的 AbilitySet、InputConfig、GameFeatureData 或 UE 编辑器资产反射：`lyra-editor-asset-automation`；
   - 普通 Blender 模型与导出脚本：`blender-asset-workflow`；
   - Raft 独立船体资产族：`raft-hull-asset-workflow`；
   - 没有领域 Skill 的通用 Python：只使用本 Skill。
5. 只有完成前四步后，才可以创建、编辑或审计脚本内容。

审计任务默认只读；本 Skill 不把“审计”扩张成修改脚本、删除资产、运行宿主程序或提交代码的权限。

## 报错后的停止条件

以下任一信号视为 Python 失败：Python `Traceback`、`Error`、未处理 `Exception`、脚本主动抛出的 `RuntimeError`、宿主明确报告脚本未执行或执行失败。

收到失败信号后：

1. 保留从首个错误到 traceback 末尾的原文，并识别宿主、入口命令、脚本路径和首次失败行。
2. **在下一次脚本修改之前**，先在失败档案新增记录；若签名与已有记录相同，则更新原记录的发生次数、复发原因和本次上下文，不新建重复条目。
3. 状态先记为 `OPEN`。只有宿主环境实际重跑成功后才能改为 `VERIFIED`；AST 解析或静态审查只能记为 `STATIC_ONLY`。
4. 如果同一错误复发，必须解释上一条预防规则为什么没有生效，并增加可以实际阻断复发的门禁。禁止仅重复同一个修补。
5. 与脚本无关的引擎版本、DDC、资产兼容性警告可以写入该次记录的“伴随噪声”，但不要冒充脚本根因。

每条记录至少包含：错误 ID、日期、宿主与入口、脚本、原始错误、首次错误转换、根因、预防规则、修复、验证证据、状态和发生次数。记录不得包含令牌、账号、私钥或其他秘密。

## 编写前门禁

动手前先回答并用仓库证据验证：

- 脚本由哪个解释器运行：Unreal Editor、Unreal Commandlet、Blender，还是普通 CPython？不要把一种宿主的入口命令复制给另一种宿主。
- 使用的 API 签名从哪里确认？优先顺序是当前仓库已成功调用、对应引擎/宿主源码或反射、官方文档。不得凭记忆省略位置参数或猜测 Python 暴露名。
- 目标对象在 Python 中的实际包装类型是什么？`get_class()` 能看到派生类，不代表基类包装器能读取派生属性。
- 修改是否幂等？脚本拥有的数组用稳定键重建，不能用 UObject/USTRUCT 包装器身份比较，也不能累加同名 GameFeature Action。
- 是否会删除或移动资产？必须先保存已清理的引用者，再查询剩余 referencer；存在未知引用时停止，不强删。
- 失败发生在资产保存前还是保存后？不要把内存中的半成品误判为磁盘已修复。

## 验证门禁

Python 改动至少完成：

1. 用 `ast.parse` 做无副作用语法检查；它不代表宿主 API 可用。
2. 在正确宿主中执行。Unreal Output Log 的 `Cmd` 模式运行文件使用 `py "<absolute-script-path>"`，不要输入裸 `exec(open(...))`。
3. 资产生成或迁移脚本连续运行两次；第二次不得增加数组条目、重复 Action 或改变已稳定资产。
4. 检查脚本自己的成功标记、保存日志和目标资产读回；不能仅以进程退出码判断 Unreal Commandlet 成败。
5. 运行 `git diff --check`，确认没有意外二进制或范围外改动。

当前环境无法运行对应宿主时，必须明确标记 `STATIC_ONLY`，给出用户可直接执行的命令和预期成功日志；不得声称已经验证。

## 与失败档案的维护关系

- 失败档案只存发生过的项目事实和紧凑预防规则；长篇领域实现留在相邻 Skill，档案用链接或技能名指向它。
- 修复经过宿主验证后，在同一次任务中更新状态与证据。
- 新错误先追加，禁止覆写或删除旧记录。错误分类有误时保留原文，并追加更正说明。
- 若档案增长影响完整阅读，把已验证的同根因记录合并为一条并保留每次发生日期；不得为了缩短文件丢失错误签名。

## 完成判据

只有同时满足以下条件，Python 工作才算完成：相关历史错误已复核；本次新错误已留档；脚本通过可用层级的验证；未验证项和宿主重跑步骤已明确；没有越权删除、运行 GUI、提交或推送。
